# 性能优化：连续供数、后台预取与系统执行

当前保留16个INT8 MAC、INT32累加、模型、量化、描述符与8×8/16/16分块规则，优化计算和搬运的组织方式。X/W扩展为双slot并各自四路分bank，卷积scratch用满原定40KiB预算。PicoRV32第三方源码未改动。

前后测量见[性能表](../results/performance.md)与[JSON](../results/performance.json)。原版记录在performance_baseline.json，上一轮4拍供数版本记录在performance_stage1.json。不要把原版、上一轮与当前版本的M/F百分比混用；当前也优化了CPU物化路径。

## 1. 四路分bank与行旋转

每份8KiB X/W包含四个512×32位bank，各有一个读口、一个字节使能写口，不复制张量以换取多端口。W按输出通道模4分bank，因此四个输出通道可同时取权重。

设输入tile局部坐标为(x,y)，步长s为1或2，输出tile宽为tw。X优先采用：

```text
bank = (floor(x/s) + floor(y/s) * tw) mod 4
```

四个连续输出位置的输入坐标是(px*s+kx, py*s+ky)。代入后bank为“输出展平索引+同一kernel位置的常量”模4，因此跨短行、奇数宽行也可无冲突取四个输入。局部地址移除bank位，并为行分配必要的对齐空间。

行填充后的最大单bank容量必须不超过2KiB；不满足时改用紧凑线性布局，逐K检查冲突并回退逐lane取数。布局选择只影响物理位置，不改变NHWC/OHWI的主存约定。大tile、stride2、容量回退和两种融合ORDER由压力测试覆盖。

GATHER_A一拍读取完整向量，并让核心消费上一组向量；非阻塞赋值保证使用旧avec/bvec。最后MAC_STEP排空一次。若实际归约长为K，无冲突时用K+1拍，长K接近16 MAC/cycle；冲突回退的一个K位置用4拍。第一轮为4K+1拍，原版为10K拍。以上均不包含微块初始化、装载、部分和、量化、写回及CPU工作。

## 2. 跳过无效计算与压缩收尾

最后一个输入通道块只遍历ci_count个有效通道，kernel位置切换时直接跨过TIC中的补零通道。输入Cin=3的首层不再按TIC=16计算另外13个零通道。输出通道微块也只遍历到实际co_count，最后四列中的无效列明确送零。独立输出的K累加顺序不变。

因此实际COMPUTE_CYCLES可以小于历史记录；这是跳过补零工作，不是漏算。测试平台根据空间tile、有效输出通道微块数、kernel与真实Cin独立检查MAC步数，并逐字节验证数值。P第一次预取1拍，连续恢复16拍，共17拍；保存P与最终结果导出各16拍。量化参数跨相同输出通道的空间微块复用。

## 3. 双slot后台预取

活动slot用于当前通道块计算，另一个slot由tile_prefetch填充下一通道块的W和X。预取范围限定为同一空间/输出通道tile的下一Cin块；不推测其他层，也不跨输出tile复用权重。

- 普通X按虚拟输入tile扫描，越界与Cin尾部补零，满足对齐/有效通道条件时整字读取/写入。
- 融合X将虚拟高分辨率坐标映射到低路floor(y/2)、floor(x/2)或高路恒等坐标，按ORDER确定源通道，使用同一个requant算术模块保持精确舍入/饱和。
- 融合后台有四个字的直接映射读缓存，保留重复低路像素数据，避免相邻2×上采样位置重复请求同一批主存字。每次预取开始失效缓存。
- 第一通道块仍走前台装载器；融合首块保留源优先转换与散写。后续后台块不物化完整上采样/拼接张量。

IC_NEXT在后台完成之前等待。只有下一块X/W全部就绪才能交换slot，不能读到半填充数据。后台请求与前台描述符/量化参数请求共享原生DMA，选中的请求在ready=0时锁定，直到完成。复位取消两套状态机；压力测试含长等待，固定套件在大任务中注入复位后重跑。

这不是无限带宽或AXI突发DMA。如果装载慢于计算，PREFETCH_WAIT仍会增加；预取只把可重叠的时间隐藏，不保证所有访存免费。

## 4. 字级搬运与CPU路径

普通输入/权重支持对齐整字装载，X清零每拍32位，输出在片上/主存对齐且剩余通道足够时一次写4字节；不满足条件时保留字节选通。每个选中的写字节都由测试平台检查落在输出张量范围内，输出总字节数必须等于张量大小，避免重复写回也被数值对拍误放过。

CPU增加1KiB直接映射指令缓存：命中时不访问共享总线，冲突时替换，程序区完成写入时失效对应行，复位清有效位。普通数据访问与MMIO旁路。加速器DMA原本就被限制在数据区，因此不会绕过失效逻辑修改程序。独立缓存测试覆盖命中、冲突、数据旁路、部分写入、等待与复位。

常见2×2池化由pool_accelerator独立执行，四个INT8通道并行比较、整字写回，不增加scratch RAM；C非4倍数时逐字节回退，越界与-128输入按原来的-127初值规则处理。第三个DMA主设备通过外层仲裁接入，仍锁定未完成事务。CPU基线和其他kernel保留地址优化的软件实现。独立测试含100组随机数据、5组非法配置和等待/复位，真实CPU小图另验证打包通道、尾通道与B0回退。上采样/拼接为两个源分别建立256项INT8精确转换表，逐元素查表替代逐元素64位乘移；地址除法移出通道循环。切片通过对齐32位memcpy复制；拼接和上采样每次读取/写入四个字节，并对非恒等尺度逐字节精确查表。恒等尺度通过SWAR将每个0x80字节饱和为0x81，避免直接复制-128改变原语义；不对齐/尾字节回退。系统小图覆盖完整INT8域、两种ORDER、不同尺度、对齐与不对齐、切片字复制与尾部。没有近似激活、精度放宽或变化的量化参数。

## 5. 资源与综合边界

| 项目 | 存储量 | 说明 |
|---|---:|---|
| X | 2×8KiB | 每slot四个2KiB bank |
| W | 2×8KiB | 同上 |
| P / O | 各4KiB | 单读/单写，分阶段使用 |
| 卷积scratch | **40KiB** | 达到原定预算，无张量存储复制 |
| 指令缓存 | 1248B | 1024B数据+192B标签+32B有效位，另外统计 |
| 后台读缓存 | 16B数据+116bit标签/有效位 | 四个主存字，另外统计 |

CSR、描述符寄存器、MAC累加器、量化参数与前台单字读缓存等控制状态另外存在，不能把40KiB说成整个SoC所有存储之和。

synth.sh检查16个物理X/W小bank及P/O的容量、单读/单写端口，并单独检查指令缓存数据/标签结构。结果在synthesis.json与cache_synthesis.json。当前只是RTL结构和存储收集；尚无特定FPGA的BRAM映射、DSP映射、布局布线、可达频率或功耗证明。地址生成中仍有动态除法/乘法，TIC分解已部分改为移位、kernel分解为常数运算，但还需要实际器件时序结果指导优化。

## 6. 计数器和验证

六组互斥阶段计数器LOAD/GATHER/PARTIAL/PARAM/OUTPUT/CONTROL之和等于JOB_CYCLES。后台与前台重叠，后台忙时间不能再与六组相加。IC_NEXT等待属于CONTROL；前台读的DISPATCH/BUS按read_return归类。READ_WORDS/DMA_WAIT包含前台和后台实际DMA活动。

新增FAST_GATHER、SERIAL_GATHER、PREFETCH_ACTIVE、PREFETCH_MAC、PREFETCH_WAIT，详见[接口](interfaces.md)。FAST+SERIAL+最后排空拍数等于GATHER_CYCLES，测试逐任务检查。PREFETCH_MAC是后台忙与实际MAC同时发生的周期，不代表额外执行了MAC。

```bash
bash scripts/run_all.sh quick  # 池化、缓存、转换器、0/3/15等待算子、压力测试、CPU小图、探针、结构综合
bash scripts/test_ablation.sh # 同一源码关闭并行取数/关闭预取，各自完整对拍
bash scripts/run_all.sh full  # 加上M/F两模型子图及整网、检测框与性能汇总
```

完整模型的每层由CPU哈希和测试平台逐字节双重检查，CPU解码/NMS另外与NumPy对照。AP由独立主机精度流程报告，等价RTL调度不应改变其结果。延迟3/15使用固定随机种子，但事务数量改变后随机延迟与地址的对应关系会改变，delay=0是更严格的周期对照。

ENABLE_BANKED_GATHER和ENABLE_PREFETCH是加速器编译参数；ENABLE_ICACHE是SoC编译参数，默认全部开启。关闭预取仍可运行同一描述符；FLAGS.bit1保持旧保留位语义，不用于选择当前自动双缓冲。消融脚本只关闭对应机制，其余代码与测试数据相同，不通过不同模型伪造收益。

## 7. 当前仍未覆盖的优化

计算阵列仍为16 MAC；尚未增加更大阵列或整网逐层流式流水，当前池化是独立外设，并非卷积-池化流式融合。外部仍为32位、单在途完成握手，不是带突发/多在途的真实DDR系统。跨空间/输出通道tile的输入/权重仍可能重读，输出排空没有与下一输出tile计算重叠；导出器尚未自动搜索分块。

这些方向需要结合剩余阶段占比、器件资源和时序决定。当前有可测量的供数与预取后，再扩大阵列才有依据；没有具体板卡与物理实现结果，不能承诺论文级FPS或功耗。周期ROI排除主机预处理、镜像装载、验证和打印，解码/NMS单独测量，仿真的wall_s不能当硬件延迟。
